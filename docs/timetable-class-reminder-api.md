# 시간표 수업 시작 1시간 전 알림

로그인 사용자가 구성한 개인 시간표의 각 수업 시작 60분 전에 개인 알림함과 Expo 발송 큐에 알림을 생성한다.

## 동작 기준

- 한국 시간(`Asia/Seoul`)으로 실제 수업 날짜·요일·시각을 계산한다.
- 수업 날짜의 연도와 학기를 사용한다. 기존 캠퍼스맵과 같이 1~6월은 1학기, 7~12월은 2학기다.
- 개강/종강일·공휴일·휴강/보강 데이터는 현재 시간표에 없으므로 자동 제외하지 않는다. 방학 중에도 해당 학기 시간표와 요일이 일치하면 동작한다.
- 학교 강좌와 직접 추가한 과목 모두 대상이다. 학교 강좌는 기존 `CoursePeriodTimePolicy`로 교시를 변환하고, 직접 과목은 저장한 시작 시간을 사용한다.
- 같은 날의 연속 교시는 첫 시작에만 한 번 알린다. 중간에 빈 교시가 있으면 별개의 수업으로 처리한다.
- 사이버 강좌, 비활성 학교 강좌, 시간이 없거나 시작 교시를 실제 시각으로 변환할 수 없는 수업은 제외한다.
- 시간표 과목과 실제 수업 시작 날짜/시각 조합당 한 번만 생성한다. 다음 주 같은 수업은 새로운 알림이다.
- 여러 서버의 동시 실행은 시간표 행 잠금과 DB 유일 제약으로 중복 생성을 방지한다. 이력·알림함·발송 큐는 하나의 트랜잭션으로 저장한다.
- 대상 기기가 없어도 사용자 개인 알림함에는 생성된다. Expo 푸시는 해당 사용자에 연결된 활성 기기로만 발송한다.

## 발송 시각

예: 월요일 10:00 자료구조 수업 → 월요일 09:00 이후 첫 실행에서 생성.

- 수업 확인 작업과 기존 발송 작업은 각각 30초 간격이다. 처리 시간과 Expo/단말 지연이 더해지므로 초 단위 도착을 보장하지 않는다.
- 목표 시각보다 먼저 생성하지 않는다. 짧은 작업 지연을 위해 최근 2분 이내의 미처리 알림만 보완한다.
- 2분 이상 지난 미생성 알림은 뒤늦게 만들지 않는다.
- 목표 알림 시각에서 5분이 지난 큐 항목은 `EXPIRED`로 처리하고 Expo에 보내지 않는다. 알림함 기록은 유지된다.
- 수업 시작 시간이 자정 이후라면 전날에 알릴 수 있다. 연도·학기 경계도 수업 날짜를 기준으로 판단한다.
- 알림 생성 전에 과목을 삭제하면 대상에서 제외된다. 이미 생성되거나 전달된 알림은 소급 회수하지 않는다.

## 프론트 연동

별도의 시간표 알림 구독/발송 API는 없다. 기존 시간표 저장 API를 그대로 사용한다.

1. 로그인 후 `Authorization: Bearer {accessToken}`을 포함해 `PUT /api/v1/push-tokens`를 호출한다.
2. 동일 설치에서는 같은 `installationId`를 유지한다. 토큰 갱신 및 재로그인 시 다시 등록한다.
3. Android는 기존 `general-v1` 채널을 준비한다.
4. Expo 수신 및 알림함에서 `type=schedule`, `subType=class_start_reminder`를 처리한다.
5. 로그아웃할 때 `DELETE /api/v1/push-tokens/{installationId}`로 사용자 연결을 해제한다. 로컬 JWT만 지우면 서버의 기기 연결은 남는다.

알림 예시:

```json
{
  "title": "[수업 알림] 자료구조",
  "body": "자료구조 수업 시작 1시간 전입니다.",
  "data": {
    "version": 1,
    "type": "schedule",
    "subType": "class_start_reminder",
    "route": "/timetable",
    "entityId": "42",
    "timetableCourseId": "103",
    "year": 2026,
    "semester": 2,
    "startsAt": "2026-09-07T10:00:00+09:00",
    "minutesBefore": 60
  }
}
```

- `entityId`: 시간표 ID 문자열. 과목 ID가 아니다.
- `timetableCourseId`: 개인 시간표에 담긴 과목 항목 ID 문자열.
- `year`, `semester`: 이동할 시간표의 연도·학기.
- `startsAt`: 날짜와 한국 시간 오프셋을 포함한 수업 시작 시각.
- 알림 선택 시 `/timetable` 화면에서 해당 연도·학기를 열고 필요하면 해당 과목을 강조한다.
- `GET /api/v1/notifications?installationId=...&page=0&size=10`에서도 조회된다. 여기서는 `data` 객체 대신 `payloadData` JSON 문자열을 파싱한다.
- 알림함과 읽지 않은 개수는 전체 알림과 개인 알림을 합쳐 최신 20건 기준이다. 읽음 상태는 설치별이다.
- 사용자별 알림 ON/OFF API는 이번 구현에 추가하지 않았다. 현재 시간표에 따라 자동 적용한다.

## 배포

1. 운영 DB를 선택하고 `docs/timetable-class-reminder-migration-mysql.sql`을 코드보다 먼저 적용한다.
2. `notification_outbox.expires_at`(UTC, nullable), 발송 상태 인덱스, `timetable_class_reminders`의 유일 제약/FK를 확인한다.
3. 새 코드를 배포하고 JPA 스키마 검증 및 서버 시작 로그를 확인한다.
4. 로그인 기기에서 토큰 재등록 후 테스트 수업을 등록하고 알림함 → Outbox → Expo → 실제 단말 순으로 확인한다.

기본적으로 켜지며 추가 환경변수는 필수가 아니다. 운영에서 중지하려면:

```properties
app.timetable-reminder.enabled=false
```

기능 활성화 값은 `true`이며, 환경변수 이름은 `APP_TIMETABLE_REMINDER_ENABLED`다. 이 설정은 새 알림 생성 작업만 제어한다. 이미 생성된 큐 항목은 기존 발송 작업이 처리한다.

기존 Expo 서버 설정과 개인 알림 대상 컬럼 마이그레이션은 선행 조건이다. 서버용 Expo Access Token은 프론트에 전달하지 않는다.

## 검증 범위

자동 테스트는 실제 저장된 시간표 → 개인 알림함/Outbox → 모의 Expo 전송까지 검증한다. 실제 운영 DB에 SQL을 적용하거나 실기기 푸시를 발송하지는 않는다.
